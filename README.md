# 모행 AI Server

> AI 기반 행사 위험도 분석 및 검수 지원 서버

본 프로젝트는 4인 팀 프로젝트로 진행되었으며,
해당 저장소는 개인 포트폴리오 제출을 위해 정리한 사본입니다.

## 핵심 기여

- AI 기반 행사 검수 기능 제안
- IBM Watsonx 기반 위험도 분석 기능 구현
- FastAPI 기반 AI 서버 구축
- 위험도 점수(risk_score) 반환 API 구현

## 프로젝트 소개

모행(MOHAENG)은 지역 기반 행사 정보를 공유하고 참여할 수 있는 플랫폼입니다.

본 저장소는 행사 등록 시 AI를 활용하여 행사 내용을 분석하고 위험도를 평가하는 AI 검수 서버입니다.

AI가 분석한 위험도 점수를 기반으로 관리자 검수 여부를 판단하여 서비스 운영을 지원하도록 설계하였습니다.

## AI 서비스 아키텍처

행사 등록 시 백엔드가 AI 서버를 호출하고, AI 서버는 IBM Watsonx를 이용하여 위험도 점수를 분석한 뒤 결과를 반환합니다.

사용자는 직접 AI 서버에 접근하지 않으며, 모든 요청은 Spring Boot 백엔드를 통해 전달됩니다.

또한 JWT 기반 사용자 인증과 내부 API Key 인증을 적용하여 서비스 보안을 강화하였습니다.

## AI 검수 기능

행사 등록 시 행사 정보를 분석하여 위험도 점수를 반환합니다.

### 입력 데이터

- 행사 제목
- 행사 상세 설명

### 처리 과정

1. 사용자가 행사 등록
2. 프론트엔드에서 백엔드 API 호출
3. 백엔드에서 AI 서버 요청
4. AI 서버가 IBM Watsonx에 분석 요청
5. 위험도 점수 산출
6. 결과 반환
7. 관리자 검수 여부 판단

### 출력 데이터

```json
{
  "risk_score": 0.82
}
```

---

## Prompt Engineering

AI가 행사 제목과 상세 설명을 분석하여 행사 위험도를 0.00 ~1.00 사이 점수로 평가하도록 프롬프트를 설계하였습니다.

위험도 점수는 관리자 검수 프로세스의 기준 데이터로 활용됩니다.

---

---

## 예외 처리

### AI 응답 파싱 실패

#### 문제

AI 응답 형식이 예상과 다르게 반환되는 경우 위험도 점수 추출에 실패할 수 있었습니다.

#### 해결

파싱 실패 시 기본 점수(1.00)를 반환하고 검수 대상에 포함되도록 처리하였습니다.

#### 결과

- 서비스 중단 방지
- AI 응답 오류 상황에서도 관리자 검수 가능
- 검수 누락 방지

## 프로젝트 회고

AI 검수 기능은 프로젝트 초기에 존재하지 않았던 기능이었습니다.

프로젝트 진행 중 기능을 추가하면서 백엔드와 프론트엔드의 수정이 함께 필요했고, 이를 통해 AI 기능 역시 서비스 전체 흐름 속에서 설계되어야 한다는 점을 경험할 수 있었습니다.

또한 AI가 항상 정확한 판단을 내릴 수 없다고 생각하여 관리자 검수 기능과 신고 기능을 함께 설계하였으며, AI를 대체하는 수단이 아닌 보조 수단으로 활용하는 방향으로 시스템을 구성하였습니다.
